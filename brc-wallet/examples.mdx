<Note>
These examples show the wallet request shape. Use
[`WalletClient`](https://www.npmjs.com/package/@bsv/sdk) in a production
TypeScript app when possible; the small `fetch` helper below makes the HTTP
contract visible.
</Note>

## Call the Desktop bridge

```ts
const bases = ['https://127.0.0.1:2121', 'http://127.0.0.1:3321']

async function walletCall<T>(method: string, args: unknown = {}): Promise<T> {
  let lastError: unknown

  for (const base of bases) {
    let response: Response
    try {
      response = await fetch(`${base}/${method}`, {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          originator: location.host,
        },
        body: JSON.stringify(args),
      })
    } catch (error) {
      lastError = error
      continue // Transport failed before a wallet response; try fallback.
    }

    const body = await response.json()
    if (!response.ok) {
      // The wallet answered. Do not replay a mutation on the fallback port.
      throw new Error(`${body.code ?? response.status}: ${body.description}`)
    }
    return body as T
  }

  throw lastError
}
```

Browsers send their own `Origin`; Desktop uses it as the app identity. Never
claim another site's origin. Probe `POST /getVersion` for BRC-100 discovery;
`GET /health` only proves that the HandCash listener is running.

## Connect and inspect the wallet

```ts
const status = await walletCall<{ authenticated: boolean }>('isAuthenticated')

if (!status.authenticated) {
  const connected = await walletCall<{ authenticated: boolean }>(
    'waitForAuthentication',
  )
  if (!connected.authenticated) throw new Error('User did not connect')
}

const [{ network }, { satoshis }] = await Promise.all([
  walletCall<{ network: string }>('getNetwork'),
  walletCall<{ satoshis: number }>('getBalance'),
])

const { publicKey: identityKey } = await walletCall<{ publicKey: string }>(
  'getPublicKey',
  { identityKey: true },
)
```

`getBalance` is a HandCash convenience extension. For portable BRC-100 apps,
derive the view you need from standard wallet methods instead of requiring it.

## Pay BSV

Construct the recipient locking script with your Bitcoin protocol library,
then let the wallet select funding, add change, sign, and broadcast:

```ts
const result = await walletCall<{ txid?: string; tx?: number[] }>(
  'createAction',
  {
    description: 'Pay coffee shop',
    labels: ['coffee-order', 'order:7842'],
    outputs: [
      {
        lockingScript: recipientP2pkhLockingScriptHex,
        satoshis: 25_000,
        outputDescription: 'Coffee order 7842',
      },
    ],
  },
)

console.log(result.txid)
```

The wallet prompt uses `description`, output amounts, and protocol context.
Make descriptions specific and human-readable.

## Stage, sign, or abort an action

Use the two-step flow when your application must add unlocking scripts or
coordinate another signer:

```ts
const staged = await walletCall<{
  signableTransaction?: { reference: string; tx: number[] }
}>('createAction', {
  description: 'Complete contract spend',
  inputs: [
    {
      outpoint: contractOutpoint,
      inputDescription: 'Application contract',
      unlockingScriptLength: 108,
    },
  ],
  outputs: [
    {
      lockingScript: nextContractLockingScriptHex,
      satoshis: nextContractSatoshis,
      outputDescription: 'Next contract state',
    },
  ],
  options: { signAndProcess: false },
})

const reference = staged.signableTransaction!.reference

// Finish:
await walletCall('signAction', {
  reference,
  spends: {
    0: { unlockingScript: contractUnlockingScriptHex },
  },
})

// Or abandon before signing:
// await walletCall('abortAction', { reference })
```

Use one path only. Do not call `abortAction` and then create a competing
transaction that spends the same input.

## Read action history

```ts
const history = await walletCall('listActions', {
  labels: ['coffee-order'],
  labelQueryMode: 'all',
  includeLabels: true,

  limit: 25,
  offset: 0,

```

Pagination is mandatory for unbounded histories.

## Read collectables

Ask for the smallest useful BRC-165 scope:

```ts
// One collection
const items = await walletCall('listOutputs', {
  basket: 'p 1sat collection',
  tags: ['collection:robots'],
  tagQueryMode: 'all',
  includeTags: true,
  includeCustomInstructions: true,
  include: 'entire transactions',
  limit: 50,
  offset: 0,
})

// One exact wallet row
const item = await walletCall('listOutputs', {
  basket: 'p 1sat id',
  tags: ['id:7f3e...'],
  tagQueryMode: 'all',
  includeTags: true,
  includeCustomInstructions: true,
  limit: 1,
})
```

Do not query bare basket `1sat`: that is wallet-internal inventory and is
refused to third-party apps.

## Mint a collectable

Your app builds the valid ordinal/1Sat locking script. HandCash funds and signs
the transaction, files the output, stamps a BRC-164 row ID, and asks the user
to approve a **Mint item** action:

```ts
const result = await walletCall('createAction', {
  description: 'Mint Robot #42',
  labels: ['1sat', 'item', 'app:robot-foundry'],
  outputs: [
    {
      lockingScript: ordinalInscriptionLockingScriptHex,
      satoshis: 1,
      outputDescription: 'Robot #42 collectable',
      basket: 'p 1sat app',
      tags: [
        'ordinal',
        'app:robot-foundry',
        'collection:robots',
        'name:Robot #42',
      ],
      customInstructions: JSON.stringify({
        name: 'Robot #42',
        app: 'robot-foundry',
        collection: 'robots',
        mediaType: 'image/png',
      }),
    },
  ],
})
```

The basket does not create the inscription. Validate your generated script
against the item protocol before sending it to the wallet.

## Receive an item

When another party gives your app an AtomicBEEF transaction, internalize the
exact output with basket insertion metadata:

```ts
await walletCall('internalizeAction', {
  tx: atomicBeefBytes,
  description: 'Receive Robot #42',
  labels: ['1sat', 'receive-collectable'],
  outputs: [
    {
      outputIndex: 0,
      protocol: 'basket insertion',
      insertionRemittance: {
        basket: 'p 1sat app',
        tags: [
          'ordinal',
          'app:robot-foundry',
          'collection:robots',
          'origin:<genesis-txid>_0',
          'name:Robot #42',
        ],
        customInstructions: JSON.stringify({
          origin: '<genesis-txid>_0',
          name: 'Robot #42',
          app: 'robot-foundry',
          provenance: brc150Provenance,
        }),
      },
    },
  ],
})
```

The wallet validates before acknowledging receipt. Do not mark delivery
complete until `internalizeAction` succeeds.

## Transfer or burn an item

An item transfer is a `createAction` that spends the held tip and creates the
protocol's next one-satoshi tip. The following advanced pattern applies when
your app knows the held output's unlock recipe and can construct the complete
unlocking script. A burn is a protocol-valid terminal spend:

```ts
await walletCall('createAction', {
  description: 'Send Robot #42',
  labels: ['1sat', 'send-collectable', 'p 1sat input id 7f3e...'],
  inputBEEF: itemInputBeef,
  inputs: [
    {
      outpoint: heldItemOutpoint,
      inputDescription: 'Robot #42 1Sat tip',
      unlockingScript: itemUnlockingScriptHex,
    },
  ],
  outputs: [
    {
      lockingScript: recipientItemTipLockingScriptHex,
      satoshis: 1,
      outputDescription: 'Robot #42 transfer',
    },
  ],
})
```

The BRC-165 input label must resolve to exactly one held row and that outpoint
must appear in the action. Preserve the item's identity and BRC-150 lineage;
never silently replace a failed item path with a plain payment. If the app
supplies only `unlockingScriptLength`, `createAction` returns a staged
transaction and the app must complete that exact reference with `signAction`.
The wallet does not expose a root private key or invent an application
contract's unlock.

## Deploy and mint a BSV-21 token

Build the current BRC-162/BSV-21 token locking script in your protocol library.
HandCash also accepts supported JSON `deploy+mint` outputs. It recognizes the
mirrored operation metadata as an identity-backed mint and adds the wallet's
issuer attestation during approval:

```ts
const payload = {
  p: 'bsv-20',
  op: 'deploy+mint',
  sym: 'ROBOT',
  amt: '1000000',
  dec: '2',
}

await walletCall('createAction', {
  description: 'Mint 10,000 ROBOT',
  labels: ['bsv21', 'handcash-mint-token'],
  outputs: [
    {
      lockingScript: bsv21DeployMintLockingScriptHex,
      satoshis: 1,
      outputDescription: 'ROBOT deploy and mint',
      basket: 'bsv21',
      tags: [
        'bsv21',
        'op:deploy+mint',
        'sym:ROBOT',
        'amt:1000000',
        'dec:2',
      ],
      customInstructions: JSON.stringify(payload),
    },
  ],
})
```

Amounts are integer base units encoded as strings. The wallet does not invent
the BSV-21 script from tags or `customInstructions`; those fields mirror and
index the protocol output your app constructed. Prefer the current BRC-162
encoding for new tokens; legacy JSON and `1sat-ft` compatibility must not be
treated as the new-product path.

## Receive or transfer BSV-21

Receive a token output with `internalizeAction`:

```ts
await walletCall('internalizeAction', {
  tx: atomicBeefBytes,
  description: 'Receive 25 ROBOT',
  labels: ['bsv21', 'receive-token'],
  outputs: [
    {
      outputIndex: 2,
      protocol: 'basket insertion',
      insertionRemittance: {
        basket: 'bsv21',
        tags: [
          'bsv21',
          `bsv21:${tokenId}`,
          'amt:2500',
          'sym:ROBOT',
          'dec:2',
        ],
        customInstructions: JSON.stringify({
          p: 'bsv-20',
          op: 'transfer',
          id: tokenId,
          amt: '2500',
          sym: 'ROBOT',
          dec: 2,
        }),
      },
    },
  ],
})
```

Transfer tokens with `createAction` just as you transfer an item: spend the
exact token tips, provide their BEEF, and create protocol-valid transfer and
change outputs. Preserve total base units exactly.

## Derive a key and sign data

```ts
const protocolID: [number, string] = [2, 'robot foundry documents']
const keyID = 'invoice:7842'
const data = [...new TextEncoder().encode('Invoice 7842 approved')]

const { publicKey } = await walletCall<{ publicKey: string }>('getPublicKey', {
  protocolID,
  keyID,
  counterparty: 'anyone',
})

const { signature } = await walletCall<{ signature: number[] }>(
  'createSignature',
  { protocolID, keyID, counterparty: 'anyone', data },
)

const { valid } = await walletCall<{ valid: boolean }>('verifySignature', {
  protocolID,
  keyID,
  counterparty: 'anyone',
  data,
  signature,
})
```

The signature prompt is per request. `counterparty: "anyone"` makes the
derived public key suitable for public verification; use a specific
counterparty for pairwise contexts.

## Encrypt data or authenticate it with HMAC

```ts
const context = {
  protocolID: [2, 'robot foundry private records'] as [number, string],
  keyID: 'record:7842',
  counterparty: 'self',
}
const plaintext = [...new TextEncoder().encode('private payload')]

const { ciphertext } = await walletCall<{ ciphertext: number[] }>('encrypt', {
  ...context,
  plaintext,
})

const { plaintext: restored } = await walletCall<{ plaintext: number[] }>(
  'decrypt',
  { ...context, ciphertext },
)

const { hmac } = await walletCall<{ hmac: number[] }>('createHmac', {
  ...context,
  data: plaintext,
})

const { valid } = await walletCall<{ valid: boolean }>('verifyHmac', {
  ...context,
  data: plaintext,
  hmac,
})
```

Use encryption for confidentiality and HMAC for integrity/authentication.

## Certificates and discovery

Certificate acquisition depends on the certifier's BRC-52 flow. Once held,
the portable read/disclosure pattern is:

```ts
const held = await walletCall('listCertificates', {
  certifiers: [certifierIdentityKey],
  types: [certificateType],
  limit: 20,
  offset: 0,
})

const proof = await walletCall('proveCertificate', {
  certificate: selectedCertificate,
  fieldsToReveal: ['name', 'country'],
  verifier: verifierIdentityKey,
})

const discovered = await walletCall('discoverByAttributes', {
  attributes: { country: 'CA' },
  certifiers: [certifierIdentityKey],
  types: [certificateType],
  limit: 20,
  offset: 0,
})
```

`proveCertificate` asks the user to approve the exact fields being revealed.

## Handle errors explicitly

```ts
try {
  await walletCall('createAction', action)
} catch (error) {
  // Examples: WALLET_LOCKED, NOT_AUTHENTICATED, PERMISSION_DENIED,
  // ACTION_DENIED, INSUFFICIENT_FUNDS, OFFLINE_PAYMENTS_DISABLED,
  // USE_P1SAT_SCOPE, ITEM_VIEW_DENIED, TOKEN_VIEW_DENIED.
  showActionFailure(error)
}
```

Never interpret a timeout or lost HTTP connection as transaction failure.
Reconcile by action label, returned `txid`, or protocol state before retrying a
mutation.
